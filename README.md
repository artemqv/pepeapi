# PepeChat

**Личные диалоги на Go и PostgreSQL. От первого входа до истории, которая переживает перезапуск сервера.**

PepeChat начинался как учебный API. Сегодня это мессенджер, который можно открыть в браузере, показать другу через Pinggy и продолжить переписку после перезапуска. Достаточно знать `@username` собеседника.

За простым действием «открыть чат» стоит работа бэкенда. Сервер проверяет сессию, находит собеседника и гарантирует один диалог на двоих, даже если оба нажали кнопку одновременно. Доступ к истории получают только участники чата.

## Что работает

- Регистрация и вход по имени пользователя и паролю. Пароли хешируются через Argon2id. Сервер хранит хеш токена сессии, а браузер получает токен в `HttpOnly` cookie.
- Личные диалоги. Для каждой пары пользователей существует один чат, даже если оба открывают его одновременно. Стороннего пользователя нельзя добавить в личный диалог через API.
- Список чатов, чтение истории и отправка сообщений. Сервер берёт ID автора из сессии и проверяет членство в чате перед чтением или записью.
- Веб-интерфейс для компьютера и телефона. Страница встроена в Go-сервер и открывается по адресу `/`.

Браузер отправляет сообщения по HTTP и обновляет историю открытого диалога каждые четыре секунды, пока вкладка видима. Защищённый WebSocket уже принимает подключения участников чата, но его рассылка пока работает отдельно от записей в PostgreSQL. Веб-интерфейс пользуется сохранённой историей через HTTP.

## Локальный запуск

Понадобятся Go **1.26.3**, PostgreSQL и [Goose](https://github.com/pressly/goose). Docker пригодится, если PostgreSQL запускается в контейнере.

### 1. Запустить PostgreSQL

Если локальная база уже есть, запустите её и переходите к настройке `.env`. Для новой базы подойдёт контейнер:

```bash
docker run -d \
  --name pepechat-postgres \
  -e POSTGRES_USER=app \
  -e POSTGRES_PASSWORD=local_dev_password \
  -e POSTGRES_DB=myapi \
  -p 127.0.0.1:5432:5432 \
  -v pepechat-pgdata:/var/lib/postgresql/data \
  postgres:17-alpine
```

Для следующих запусков используйте `docker start pepechat-postgres`. Том `pepechat-pgdata` хранит данные между запусками контейнера.

### 2. Настроить окружение и применить миграции

Создайте `.env` в корне проекта. Значения ниже подходят для контейнера из примера. Для существующей базы подставьте её параметры.

```bash
DATABASE_URL='postgres://app:local_dev_password@localhost:5432/myapi?sslmode=disable'
```

Файл `.env` игнорируется Git. Загрузите его в текущий терминал и примените миграции:

```bash
set -a
source ./.env
set +a

GOOSE_DRIVER=postgres GOOSE_DBSTRING="$DATABASE_URL" goose -dir migrations up
```

Миграции создают базовую схему, добавляют поля аккаунтов, сессии и таблицу личных диалогов. Для открытия лички нужна миграция `00004_create_direct_chats.sql`. Статус можно проверить командой:

```bash
GOOSE_DRIVER=postgres GOOSE_DBSTRING="$DATABASE_URL" goose -dir migrations status
```

### 3. Открыть приложение

В том же терминале запустите:

```bash
go run ./cmd/server
```

Откройте [http://localhost:8080](http://localhost:8080). Чтобы проверить личку, создайте два аккаунта в разных профилях браузера. Под первым аккаунтом откройте новый чат по имени второго, отправьте сообщение и обновите страницу под вторым аккаунтом. Сообщение должно остаться в истории после перезагрузки.

## Демо через Pinggy

Оставьте Go-сервер и PostgreSQL запущенными. В другом терминале откройте туннель к приложению:

```bash
ssh -p 443 -R0:localhost:8080 free.pinggy.io
```

Откройте HTTPS-ссылку из вывода Pinggy и отправьте её собеседнику. При остановке туннеля публичная ссылка перестаёт работать. Переписка остаётся в локальной базе. [Документация Pinggy](https://pinggy.io/docs/)

## HTTP API

| Метод и путь | Доступ | Результат |
| --- | --- | --- |
| `GET /` | Открытый | Веб-интерфейс |
| `POST /register` | Открытый | `201` и данные нового пользователя |
| `POST /login` | Открытый | `200` и cookie `session_token` |
| `GET /me/chats` | Сессия | `200` и список чатов текущего пользователя |
| `POST /chats/direct` | Сессия | `200` и ID нового или существующего диалога |
| `GET /chats/{chatID}/messages` | Сессия и членство | `200` и история чата |
| `POST /chats/{chatID}/messages` | Сессия и членство | `201` и сохранённое сообщение |
| `GET /chats/{chatID}/ws` | Сессия и членство | `101` при успешном WebSocket-рукопожатии |

Регистрация принимает `username`, `display_name` и `password`. Вход принимает `username` и `password`. Cookie действует 24 часа.

Чтобы открыть диалог, отправьте на `POST /chats/direct` JSON `{"username":"@petya"}`. Ответ выглядит как `{"id":101}`. Если пользователя нет, сервер вернёт `404`, а попытка открыть чат с собой даст `400`.

Для отправки сообщения передайте на `POST /chats/101/messages` JSON `{"text":"Привет!"}`. ID автора сервер берёт из сессии. Защищённые маршруты возвращают `401` без действующей сессии и `403`, если требуется членство в чате и его нет.

Учебные маршруты `POST /chats`, `POST /chats/{chatID}/members` и `GET /items/{id}` остаются открытыми. Маршрут добавления участников возвращает `403` для личных диалогов. Для постоянной публичной эксплуатации обычным чатам ещё нужны правила создания и управления участниками.

## Как устроен PepeChat

| Путь | Назначение |
| --- | --- |
| [cmd/server](cmd/server) | Маршруты `net/http`, обработчики, middleware сессии и WebSocket Hub |
| [cmd/server/web/index.html](cmd/server/web/index.html) | Встроенный интерфейс на HTML, CSS и JavaScript |

| [internal/telemetry](internal/telemetry) | Настройка OpenTelemetry |
| [migrations](migrations) | SQL-миграции Goose |
| [Dockerfile](Dockerfile) | Сборка образа Go-сервера |
| [.gitlab-ci.yml](.gitlab-ci.yml) | Сборка и публикация образов для `amd64` и `arm64` |

Открытие личного диалога выполняется в транзакции. PostgreSQL хранит упорядоченную пару ID в `direct_chats` и гарантирует её уникальность. Если два запроса одновременно создают один диалог, один сохраняет чат и участников, а другой откатывает свою вставку и возвращает ID сохранённого чата.

## Тесты

Из корня проекта:

```bash
go test ./... -count=1
```

Этот запуск проверяет аутентификацию, HTTP-обработчики и WebSocket-рукопожатие. Интеграционный тест PostgreSQL запускается при заданной `TEST_DATABASE_URL`. Добавьте её в локальный `.env` с URL тестовой базы и экспортируйте переменные:

```bash
set -a
source ./.env
set +a
go test ./... -v -count=1
```

Интеграционный тест сам создаёт и удаляет отдельную схему. Пользователю базы нужны права на создание схемы. Тест проверяет конкурентное открытие лички, отсутствие лишнего чата и запрет на добавление третьего участника.

## Следующий шаг — чат в реальном времени

Связать сохранение и доставку сообщений. После записи в PostgreSQL сервер будет отправлять сохранённое сообщение участникам через WebSocket, чтобы собеседник увидел его сразу. При повторном подключении браузер сможет восстановить историю из базы.
